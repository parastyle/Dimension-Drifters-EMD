**Strengths:** Clean package boundaries: @dd/shared, @dd/server, @dd/client, @dd/desktop are well-separated with no cross-imports (server does not import client, and vice versa).; Single source of truth for types: ArenaState, PlayerState, WeaponDef, and all sim logic live in shared; no duplicated schemas between server/client.; Consistent .js extensions in relative imports throughout shared (e.g., './constants.js'), enabling valid Node ESM and proper hot-reload in Vite/tsx/Vitest.; Correct build order: all dev/test scripts build @dd/shared first (via tsc), ensuring legacy decorators are emitted before server/client consume the dist..

- 🟠 **Schema change fragility: no automated field validation, clients must reload on schema reordering** ✅ **FIXED**
  - _where:_ `C:/Projects/Dimension Drifters v2/packages/shared/src/state.ts (entire file, 175 lines); C:/Projects/Dimension Drifters v2/packages/server/src/rooms/GameRoom.ts:288-290 (onCreate/setState)`
  - _issue:_ Colyseus serializes schema fields by definition order in the class. If a field is reordered, renamed, or type-changed in the shared state.ts, the binary wire protocol becomes misaligned. Old clients will deserialize new patches with field offsets corrupted, leading to silent data corruption (HP reads as aim, enemy kind becomes player x, etc.). There is no version handshake, codec validation, or opt-in schema migration. The codebase relies on manual discipline: dev remembers to never reorder fields, and clients must hard-reload to fetch the new schema. This works for a 2-person team shipping a POC but will compound as the team scales.
  - _fix:_ Deferred to SPEC-01 (the SoT/data-migration pipeline). For now, document the field-order lockdown as a team convention in CLAUDE.md and add a comment at state.ts:1 with a warning. Medium-term (post-M0): implement a schema version field (uint16) on ArenaState, and have clients assert the server schema matches theirs on handshake—reject if versions diverge and log the mismatch. This prevents silent corruption and makes the constraint explicit.
- 🟡 **Patch-rate explicitly pinned to TICK_MS; underlying mismatch with Colyseus default hints version brittleness**
  - _where:_ `C:/Projects/Dimension Drifters v2/packages/server/src/rooms/GameRoom.ts:521-524`
  - _issue:_ GameRoom.onCreate pins setPatchRate(TICK_MS) (50ms, 20Hz) immediately after setSimulationInterval. The comment states 'otherwise it sits at the Colyseus default (50ms) and silently diverges from the sim if TICK_MS ever changes.' This is a red flag: Colyseus 0.16's default patch rate already IS 50ms, so the pinning is technically redundant. However, the need to pin it suggests (1) the relationship between sim tick and patch broadcast is fragile, or (2) future version upgrades might change defaults without warning.   - _fix:_ Add an explicit invariant assertion: `if (Math.abs(TICK_MS - <Colyseus default patch rate>)) > 1) { throw new Error(...) }` at startup, or bind TICK_MS to a constant exported from Colyseus directly.
