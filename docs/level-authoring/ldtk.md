# LDtk arena authoring

`data/arenas/dimension-drifters.ldtk` is the canonical authored-arena source. Open that project in LDtk 1.5.3, duplicate or edit `owner_playground`, save, then compile it with:

```powershell
pnpm --filter @dd/shared build
node tools/levels/gen-authored-arenas.mjs
```

To verify source/generated drift without writing:

```powershell
pnpm --filter @dd/shared build
node tools/levels/gen-authored-arenas.mjs --check
```

The generator is intentionally standalone until runtime integration registers it in `pnpm gen`, `pnpm gen:check`, and `pnpm assets:check`. Never edit `packages/shared/src/authored-arenas.generated.ts`; it is replaced by the generator.

## Editing loop

1. Use LDtk 1.5.3. The project and importer pin JSON version 1.5.3. If another editor version rewrites `jsonVersion`, compilation stops with the supported and observed versions instead of guessing at schema compatibility.
2. Edit the embedded level. Keep the level at 4800×4800 pixels and every layer on its 80px grid with zero offsets.
3. Paint `Terrain`: empty cells are ground; `Pit` (value 1) is hazard. No other value is legal.
4. Paint `Zones`: empty cells are Commons; `Cover` is value 1; `Scar` is value 2. Each of the three zones must be one connected footprint, and Commons must retain the centre identity core.
5. Place exactly one `PlayerSpawn` on the `Gameplay` layer. Grid snapping must leave it at the centre of its cell.
6. Save and run the compiler. Fix failures in LDtk and run it again. There is no repair mode and no procedural fallback.

The starter intentionally contains an asymmetric pit/zone silhouette and a two-cell hop notch. Preserve the border and spawn breathing room when reshaping it.

## Exact project contract

The project uses embedded levels only (`externalLevels=false`), one ordinary world, and no tilesets, Tile layers, AutoLayers, external enums, or external `.ldtkl` files. The supported definitions are exact and array order is irrelevant:

| Surface | Identifier | Contract |
|---|---|---|
| IntGrid layer | `Terrain` | 80px; empty Ground; `Pit=1` |
| IntGrid layer | `Zones` | 80px; empty Commons; `Cover=1`; `Scar=2` |
| Entity layer | `Gameplay` | 80px; PlayerSpawn only |
| Entity | `PlayerSpawn` | exactly one; no fields |
| Optional level field | `DisplayName` | non-empty string when present |
| Optional level field | `InitialDimensionId` | lowercase kebab-case dimension ID when present |

LDtk identifiers normalize from lowercase/underscore/space form to lowercase kebab case. For example, `owner_playground` compiles to `owner-playground`. Normalized IDs must be unique and match letters/numbers separated by single hyphens.

Editor ordering is never content authority. Levels compile by normalized ID, and the debug seed for each zone is its first cell in row-major order. Reordering panels, definitions, layers, fields, or entities therefore does not change generated bytes.

## Failures and coordinates

Every importer failure identifies the source, normalized level, project/layer/entity IID, tile coordinate, and world coordinate. Tile diagnostics use zero-based `(column,row)` and report the corresponding tile centre in world pixels. Entity diagnostics use the entity's exact world-pixel position.

The importer rejects schema/version drift, duplicate IDs or IIDs, definition drift, wrong layer type/grid/offset, wrong dimensions, illegal IntGrid values, missing/duplicate gameplay entities, non-centred/out-of-bounds entities, non-finite fields, and any geometry rejected by the shared `validateArena` or `auditArenaNavigation` laws. Those shared laws own reachability, border, zone topology, and pit-aware navigation; the importer does not reproduce or repair them.

When an authored level fails, change the `.ldtk` source. Do not hand-edit generated TypeScript, insert a bridge in generated data, dissolve an island, weaken an assertion, or add fallback-to-procedural behavior.

## Deliberately unsupported

M1 does not support variable arena sizes, an in-game editor, `--repair`, shop/rift entities, external levels, multi-world projects, Tile/AutoLayer rendering, tilesets, a procedural-to-LDtk exporter, public matchmaking selection, hot reload/watch RPCs, or runtime `.ldtk` loading.

Format references: [LDtk JSON 1.5.3](https://ldtk.io/json/), [JSON overview](https://ldtk.io/docs/game-dev/json-overview/), [layer instances](https://ldtk.io/docs/game-dev/json-overview/layer-instances/), and [entity fields](https://ldtk.io/docs/game-dev/json-overview/entity-fields/).
