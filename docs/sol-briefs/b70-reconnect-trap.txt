## There are TWO separate defects. Fix BOTH.

### Defect 1 — refresh should not silently hijack the session
A deliberate page refresh is not a transport failure. Reconnection exists for a Wi-Fi blip or a
dropped socket, NOT for the developer/player choosing to reload.

Decide and implement the right policy, and justify it in your report. Strong recommendation:
**refresh starts FRESH by default**, and reconnection fires on genuine unexpected transport loss.
If you keep any refresh-resume behaviour at all, it MUST be an explicit opt-in the user chooses,
never an automatic takeover.

### Defect 2 — the reconnected state is BROKEN, and that is a bug on its own
Even when reconnection is correct, the owner lands in a room with:
- no enemies
- movement locked at the spawn circle
- T (Testing Grounds) refused
- no way back to the lobby

So the restored session is not actually playable. **Diagnose why.** Candidates: the room was disposed
and recreated empty; the run is in a terminal/settled state but the client still attaches; host status
is lost so `toggleTraining` is refused (`room-progression.ts` requires `isHost`); spawn//ready gating
never releases; the wave/spawner never resumes. Find the real cause — do not paper over it.

**A reconnect that restores an unplayable room must fail loudly and fall back to a fresh session
rather than attaching.** Validate the room is actually resumable BEFORE committing the player to it.

## THE NON-NEGOTIABLE RULE
**There must ALWAYS be an escape hatch.** No state in this game may ever trap the player with no way
out. Whatever the reconnect UI does, it needs a visible, always-available way to abandon and start
fresh — and that control must work even when the underlying room is broken. The owner could not reach
the lobby, could not reach Testing Grounds, and could not move. That must be impossible by construction.

Standing law: never interrupt gameplay with a modal. The reconnect overlay is a status surface — it
must not steal input or block the view. If the current overlay is what is eating the T key or
movement input, that is squarely part of this bug.
