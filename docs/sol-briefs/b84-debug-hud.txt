## Build: an on-screen diagnostic HUD
Dev-gated behind `clientDevToolsEnabled()` — NEVER present in a production build. Toggled by a key;
check the existing bindings in `ArenaScene` (`W,A,S,D,R,P,Q,E,Z,X,F,G,H,T,B,C,M,TAB,ESC,SPACE,SHIFT,
CTRL,ONE..FIVE,arrows,ENTER`) and pick a free one. State your choice.

**Each metric shows: label, current value, and a GREEN / AMBER / RED state against a stated threshold.**
Red must mean "this is actually wrong", not "this is busy" — a HUD that is always half-red is useless.
Document every threshold and why you chose it.

### Metrics to include (all of these; add more if you find something diagnostic)
1. **Frame time** — current + rolling p99. RED above 250 ms (that is the `forceResync` trigger at
   `ArenaScene.ts:15193`), AMBER above ~33 ms.
2. **Stall count** — frames >250 ms this session. Any non-zero is RED; this is the thing that causes warps.
3. **Self corrections** — count, max px, and which band (Silent / Smooth / Snap) per B42/L10.
   A Snap on SELF is RED — canon L10 says self must never hard-snap.
4. **Render vs commit divergence** — px between the extrapolated render position and the position the
   committed input actually produces. This is the `b83-input-alias` defect; surface it as a first-class
   number. RED above a stated threshold.
5. **Input latency** — ms from key press to committed command. L10 says self must never feel lag.
6. **Server tick health** — measured interval vs `TICK_MS` (50 ms) and drift.
7. **RTT / ping** to the room.
8. **Prediction pending window** — unacknowledged inputs in flight. Growth means the client is
   outrunning the server.
9. **Entity load** — enemies, projectiles, active VFX/particles. Context for the numbers above.
10. **Heap** — `performance.memory` where available, plus growth rate. GC pressure is a live suspect.
11. **Resync count** — how many times `forceResync()` fired.

report format so someone reading it cold can tell what went wrong.
