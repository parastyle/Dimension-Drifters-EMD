## The architecture to build
1. **One presentation pass per render frame** producing a single `PresentedActorState`
   (root x/y, velocity, facing, aim, stance, action phase, and the six part transforms). NOTHING
   else may write rig transforms. Consolidate the six current writers (rig-pose 32 jiggle refs,
   rig-core 11, combat/flourish/gear/gun-mechanisms 3 each) into this one ordered pass.
2. **Body root: sim-intent only.** The root reads the authoritative/predicted LOCOMOTION intent —
   constant speed times documented modifiers ONLY: attack multiplier, hit/stagger, gun recoil
   (B45 classified impulse). It must NEVER read correction-bearing rendered positions, and no
   animation clock may derive from a corrected value (the B52 loop). Corrections move the root
   presented position smoothly per the existing banded policy — they never reach limb state.
3. **Limbs are servants, springs by DEFAULT.** Every unclaimed limb runs the shipped spring
   system continuously (PROCEDURAL_JIGGLE params: hand w10/z0.32, foot air/plant, inertia, max
   displacement) driven by body motion, turns, landings, and recoil — loose, cartoonish, always
   alive. Idle must NOT be static: body micro-motion keeps limbs floating (Interactive Buddy
   target).
4. **Claims override, then hand back.** An action claims only the limbs Lane 2 declares (a sword
   swing claims the weapon hand — the other hand and both feet KEEP flopping). On release, hand
   the limb back to springs carrying exit velocity (clamped by JIGGLE_HANDOFF_MAX_V) so it settles
   instead of snapping.
5. **One monotonic clock.** All animation phases (gait, jiggle, flip, combo) advance on a single
   never-reset accumulator wrapped continuously — no per-event resets, no tick-phase dependence.
   Interrupted flips/combos resume from current visual state.
