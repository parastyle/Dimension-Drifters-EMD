## F1 — reconnection is not implemented (M, player-visible run loss)
Today a Wi-Fi blip, refresh, or browser transport reset loses the whole run. There is no
`allowReconnection`, no `reconnectionToken`, no client `reconnect()`, and no room `onLeave`/`onError`
handler. `ArenaScene.connect()` retries `joinOrCreate`/`create` up to 30 times ONLY during cold
startup. Meanwhile the server removes the player and keys its reservation by the DEPARTED session id,
while a fresh join is issued a different id — so the reservation exists but is unreachable.

Implement per the audit's recommendation:
1. **Server**: distinguish an UNEXPECTED leave from a CONSENTED one. On unexpected transport loss,
   reserve the seat with `await this.allowReconnection(client, seconds)` for a short bounded window.
   Only a timeout or an explicit quit abandons the run. Check `autoDispose`/`onDispose` — if the last
   player drops, the default room lifecycle currently destroys the only in-memory reservation.
2. **Client**: persist `room.reconnectionToken` plus `{roomId, runId}` in `sessionStorage`. Attach
   `onLeave`/`onError` handlers IMMEDIATELY after joining. Reconnect via `client.reconnect(token)`
   with capped, jittered backoff.
3. **UI**: a non-destructive full-screen overlay showing reconnecting / recovered / run ended.
   **STANDING PROJECT LAW: never interrupt gameplay with a modal.** This overlay must not steal input
   or block the view of the run; it is a status surface, not a dialog.
