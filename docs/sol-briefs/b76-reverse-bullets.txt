Specific hypotheses worth testing, in rough priority:
1. **Facing vs aim disagreement.** Walking forward while shooting forward is the case where movement
   direction, facing, and aim SHOULD all agree — so a bug that only shows when they briefly disagree
   would be rare and unreproducible. Look for anywhere `facing`/`flipX`/mirror state is used to derive
   a muzzle direction instead of the aim vector itself.
2. **Muzzle origin/direction derived from a MIRRORED transform.** If the rig is flipped and the muzzle
   point is read in local space then transformed, a stale or double-applied flip inverts the vector.
   B68 changed how the rig presents each frame — check the muzzle sample against the new
   `PresentedActorState` rather than any older per-part read.
3. **A one-frame stale aim.** If the projectile spawns from last frame's aim while the flip already
   applied, you get an inverted shot for exactly one shot — which matches "happened once, can't repeat".
4. **Normalisation of a zero/degenerate vector.** A zero-length aim normalised can yield NaN or a
   default that points backwards. Check every `atan2`/normalise on the fire path for the degenerate case.
5. **Dual-wield / alternating-hand fire** picking the wrong hand's muzzle transform.
