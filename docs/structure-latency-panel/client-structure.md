# Client structure and contention audit — reviewer 2 of 5

## Basis, scope, and severity

This review is against committed `HEAD` `271140d`, not the working tree. I used `git show HEAD:<path>` for `ArenaScene.ts`, `AudioBus.ts`, `SpriteRig.ts`, and every tracked file under `packages/client/src/vfx/`. That matters because `ArenaScene.ts` and `AudioBus.ts` had uncommitted edits, and the requested in-flight areas also included `SpriteRig.ts` and VFX. Untracked in-flight files such as `combat-feedback.ts`, `ui/damage-numbers.ts`, `settings.ts`, and `vfx/hit-effects.ts` are deliberately excluded. All line citations below therefore refer to the committed files.

Severity is structural, not a claim of a player-visible bug:

- **P0** — currently blocks parallel client work or makes common edits collide in the same ownership/lifecycle surface.
- **P1** — a high-value boundary whose extraction will materially reduce future contention or unsafe coupling.
- **P2** — cleanup, secondary decomposition, or guardrail work that should follow the main splits.

Effort is **S** (hours to one day), **M** (roughly one to three days), **L** (three to six days), or **XL** (a staged program). “Safety high” means a mostly mechanical move can preserve behavior; “safety medium” means characterization tests or an adapter seam are prerequisites. No proposal below intentionally changes gameplay, visuals, input priority, network protocol, timings, draw depths, or asset keys.

## Ranked structural findings

### P0 — active contention blockers

1. **P0 — `ArenaScene` is the client-wide ownership graph, not a scene coordinator.** The class begins at `packages/client/src/scenes/ArenaScene.ts:765`; its fields cover room state through shop UI (`:766-1248`), and its 179 methods run through `:9815`. Every feature wave must understand and edit unrelated state. This is why input, HUD, dock, bag, level windows, telegraphs, beams, motes, worm, paper, death recap, belt, networking, assets and audio repeatedly queued on one file. **Extract:** keep `ArenaScene` as Phaser composition/lifecycle plus an explicit ordered frame pipeline, while stateful `ArenaSession`, `ArenaReplication`, `ArenaInputRouter`, `ArenaHud`, `CombatPresentation`, `PaperTransitionController`, `BeltRenderer`, and overlay views own their state. **Effort/safety:** **XL, staged / medium-high**; do not rewrite behavior—move contiguous blocks behind typed facades and keep the current update order.

2. **P0 — lifecycle fan-in forces every subsystem to touch declarations, reset, create, update, and shutdown.** `resetSceneState()` manually resets nearly the whole class over 212 lines (`packages/client/src/scenes/ArenaScene.ts:1429-1640`), `create()` constructs all services and listeners (`:1657-1788`), and `update()` calls roughly forty responsibilities in a behavior-sensitive sequence (`:2982-3187`). Adding one overlay or renderer therefore usually requires edits in three to five hot regions even before its own code. **Extract:** each controller must own `reset()`/`destroy()` and its display pools; replace the manual field census with a small `ArenaRuntime` composition record and ordered `updateInput`, `updateReplication`, `updatePresentation`, `updateHud` stages. **Effort/safety:** **L / high** when performed subsystem by subsystem; the safety argument is fewer forgotten resets and no reorder of the existing frame stages.

3. **P0 — `SpriteRig` has become the second client god object and its 1,505-line `animate()` is the only final pose writer.** The class owns 144 fields (`packages/client/src/entities/SpriteRig.ts:894-1120`), eleven combo/style methods span `:2461-4006`, and `animate()` reads or writes 133 distinct `this` members (`:4008-5512`). Recent combo, dagger/claw, jiggle, tome, remote-signature and paper-death waves all land here. **Extract:** first introduce one retained, allocation-free `RigPoseFrame` containing the current attack/body/hand/foot/shadow channels; then move pure samplers into `entities/sprite-rig/poses/`, while `SpriteRig` alone applies the sampled frame to Phaser objects. **Effort/safety:** **L / medium**; viable only with scalar pose characterization at selected normalized times and no per-frame allocation.

### P1 — high-value ownership boundaries

4. **P1 — dock layout/card art are extracted, but dock state and rendering still live in the hotspot.** A 34-field `CarouselDock` record is declared in the scene (`packages/client/src/scenes/ArenaScene.ts:300-335`); construction and the complete dormant/peek/focused/fading state machine remain at `:7933-8604`, despite pure layout in `packages/client/src/ui/weapon-dock-layout.ts:98-221` and rendering primitives in `packages/client/src/scenes/arena/card-art.ts:168-665`. The two latest dock waves therefore still collided with every other scene wave. **Extract:** `WeaponDockView` owns the record, caches, timers/tweens and card/chip objects; it accepts a read-only loadout/beam snapshot and emits `cycle`/`inspect` intents. **Effort/safety:** **M / high**; current methods form a contiguous block and use only a narrow slice of scene state.

5. **P1 — bag, arsenal, shop and persistence are one scene-owned subsystem with direct network sends.** Fields are grouped at `packages/client/src/scenes/ArenaScene.ts:1208-1231`; `updateArsenalHud()` mixes state derivation, persistence, panel choreography and shop gating (`:8671-8808`), while bag rendering and interactive zones occupy `:8940-9291`. This was a primary source of the latest dock/backpack contention. **Extract:** `InventoryPanel` owns Graphics/text/image/zone pools and renders an immutable `InventoryViewModel`; it emits `equip`, `store`, `sell`, and `buyUpgrade` intents. Move localStorage access (`:8609-8640`) to `MetaProgressRepository`. **Effort/safety:** **M / high**; preserve visual sort order and keep server bag indexes in the emitted intent exactly as today.

6. **P1 — level-up UI is split at the wrong seam: model/layout are modular, view/controller remain in the scene.** The pure model and layout are already good (`packages/client/src/ui/level-up-model.ts:184-402`, `packages/client/src/ui/level-up-layout.ts:34-151`), but 18 scene fields and all shell/card/focus/input lifecycle stay in `ArenaScene` (`packages/client/src/scenes/ArenaScene.ts:1163-1182`, `:4925-5602`). Consequently every level-UI polish wave still edits the god object. **Extract:** a `LevelWindowController` wraps those pure modules, owns its Phaser objects, and exposes `sync(player, viewport)`, `handleInput(input)`, `blocksWorldInput`, and choice intents. **Effort/safety:** **M-L / high** after tests for focus wrap, release latch, timeout label and one-send-only behavior; keep the scene-level hit zones at their current fixed-screen coordinates.

7. **P1 — telegraph geometry and telegraph rendering are large enough to be their own engine but remain embedded.** Pure geometry construction sits before the class (`packages/client/src/scenes/ArenaScene.ts:471-749`); windup sampling, full-tell selection, melee rings/brackets and exact/cadence rendering span `:3606-4494`. Telegraph changes also touch enemy animation, audio, camera shake and danger attribution, explaining the large telegraph/readability diffs. **Extract:** move the pure geometry first, then a `TelegraphRenderer` that owns Graphics, `TelegraphForeshadowPool`, cache/frame state and windup/full-tell maps. Feed it rows plus projection/camera context and have it emit typed `resolvedDanger` events. **Effort/safety:** **M-L / medium-high**; pin geometry point lists and preserve ground/edge depth plus the one-frame `t=1` handling.

8. **P1 — the beam subsystem is split across a renderer and four unrelated scene regions.** `BeamRenderer` is already independent (`packages/client/src/vfx/BeamRenderer.ts:98-451`), but prediction state is declared in the scene (`packages/client/src/scenes/ArenaScene.ts:794-820`), HUD/status is at `:7541-7645`, and aim/reconcile/update/audio feedback/fixed-command integration is at `:9533-9815`. A beam change therefore crosses HUD, net input, audio and VFX ownership. **Extract:** `BeamHud` first; then `BeamClient` owns start sequence, pending aim commands and reconciliation, while `BeamFeedback` converts phase edges into audio/shake intents. `stepNetInput` supplies the exact same command to `BeamClient` and `SelfPredictor`. **Effort/safety:** **M / medium**; test ack wrap, rejected charge fade, release/overheat transitions and command ordering before moving.

9. **P1 — damage recap is extraction-ready pure state but is interleaved with combat rendering and HUD.** Wire-shaped attribution types begin at `packages/client/src/scenes/ArenaScene.ts:359`; retained state is at `:1028-1059`; reset/copy/receipt/inference logic is `:6902-7121`; label formatting is `:7647-7708`; final display is buried in `updateHud()` (`:7711-7930`). This caused death-explanation work to collide with telegraph, beam and general HUD changes. **Extract:** `DamageRecapTracker` consumes authoritative receipts plus the current fallback observations and returns two immutable entries; `DeathRecapView` formats them. **Effort/safety:** **S-M / very high**; the tracker can be moved and unit-tested without Phaser or protocol changes.

10. **P1 — combat presentation has three homes and no single ownership rule.** Reusable effects live in `scenes/arena/vfx.ts` (for example damage numbers at `packages/client/src/scenes/arena/vfx.ts:1189`), authored weapon effects live behind `VfxPlayer` (`packages/client/src/vfx/VfxPlayer.ts:242-506`), while `ArenaScene.updateCombatFx()` and five local spawn methods remain at `packages/client/src/scenes/ArenaScene.ts:7125-7539`; chain/slash bridging appears again at `:9296-9403`. Agents must guess whether a new hit/readability effect belongs in `vfx/`, `scenes/arena/vfx.ts`, or the scene. **Extract:** define a layering rule: `vfx/runtime` owns generic render primitives, `scenes/arena/effects` owns game-semantic one-shots, and `CombatPresentation` owns receipt/edge detection and budgets. **Effort/safety:** **M-L / high** for verbatim moves; preserve the existing budget counters and event order.

11. **P1 — belt mode is a cohesive renderer hidden inside the general scene.** Belt fields are grouped at `packages/client/src/scenes/ArenaScene.ts:958-970`; theme, floor baking, projection, backdrop/clouds, gate and belt camera run at `:5853-6216`, with mode branches also leaking into input, beam aim and HUD. The world-rendering portion is at least as extraction-ready as the existing floor renderer. **Extract:** `BeltRenderer` owns art, level, projection and camera sampling and exposes `projectY`, `projectObjects`, `build`, `updateCamera`, and `destroy`; a small `ArenaProjection` interface removes repeated `this.belt ? ...` branching from effects. **Effort/safety:** **M-L / high**; retain all formulas and object-depth writes verbatim.

12. **P1 — paper moments span scene transitions, pickup exits and rig deaths without a controller.** The scene retains fold/page/death/pickup state at `packages/client/src/scenes/ArenaScene.ts:782-792`; pickup exits write into it at `:2216-2283`; world capture/fold/pool lifecycle is `:2491-2713`; enemy removal adds detached paper deaths inside `:3305-3469`. This caused the paper wave to touch pickups, floor changes, enemies, lifecycle and debug counters. **Extract:** `PaperTransitionController` owns the page pool, current fold, closing pickups, detached deaths and peak counters, with explicit `captureWorld(objects)`, `beginPickupExit`, `beginDeath`, `step`, and `destroy`. **Effort/safety:** **M / medium-high**; callers still supply objects in the same order, and the controller preserves current capture/depth/reduced-motion semantics.

13. **P1 — input routing mixes device sampling, modal policy, gameplay intent and room transport.** The top of `update()` implements grab/drop/salvage, jump, carousel/slot/gallery, debug, mute, bag and shop priority (`packages/client/src/scenes/ArenaScene.ts:2982-3132`); level-window keys are separate at `:5337-5409`; attacks and parry sample pointers directly at `:6412-6601`; fixed commands do so again at `:9779-9815`. This is a structural reason not to extract input first: several implicit priority rules would be easy to change accidentally. **Extract:** after overlays expose `blocksInput`, create an `InputRouter` that samples once and emits typed intents plus a retained `ArenaInputFrame`; the scene/session sends them in the current order. **Effort/safety:** **L / medium**; characterize grab-over-drop, modal release latch, Q/E mode routing, right-click beam/melee exclusivity and fixed-tick jump consumption.

14. **P1 — the pure net primitives are good, but the transport/replication adapter is missing.** `SelfPredictor` is intentionally Phaser/Colyseus-free (`packages/client/src/net/prediction.ts:159-404`) and `SnapshotBuffer` is similarly focused (`packages/client/src/net/snapshots.ts:92-192`). In contrast, connection retries and DOM status live in the scene (`packages/client/src/scenes/ArenaScene.ts:2862-2952`), patch ingestion creates rings and reconciles both self and beam (`:9461-9509`), and entity sync maps are scene fields. **Extract:** `ArenaSessionClient` owns connect/retry/join/leave/schema-check and emits state patches; `ArenaReplication` owns player/enemy rings and predictor reconciliation, returning render samples to the scene. **Effort/safety:** **L / medium-high**; existing net tests provide a base, and the data-only patch invariant at `:2925-2929` must remain explicit.

15. **P1 — a direct “one file per swing style” split is not yet viable because style methods mutate the rig.** The 11 `apply*` methods (`packages/client/src/entities/SpriteRig.ts:2461-4006`) each write roughly 11–24 rig fields; `animate()` dispatches them and the legacy orbit/spin/chop/pivot/punch/thrust vocabulary at `:4462-4913`. Moving bound methods into files would merely export a huge mutable context and hide coupling. **Extract:** first make each style a pure sampler `(RigPoseContext, RigPoseFrame) => weaponAngle`; group combo families by vocabulary (`heavy-combos`, `close-blade`, `orbit-spin`, `punch-thrust`), not necessarily one micro-file per weapon. **Effort/safety:** **L / medium**; viable after the retained pose-frame seam, with normalized-time golden scalar tests and no Phaser imports in style modules.

16. **P1 — jiggle, tome pages and paper death are already better extraction candidates than swing styles.** Jiggle state/math is top-level and pure (`packages/client/src/entities/SpriteRig.ts:592-822`), tome state and lifecycle are a closed block (`:606-641`, `:1678-1946`), and paper-death state/stepping is similarly bounded (`:853-881`, `:1297-1433`). They remain in `SpriteRig` mainly because final transform application happens there. **Extract:** `secondary-motion.ts` for spring state/math, `tome-visual.ts` for retained page/scrap objects, and `paper-death.ts` for detached death sampling; `SpriteRig` passes final weapon/root transforms into their `sync`/`step` methods. **Effort/safety:** **M / high** for jiggle math, **M / medium-high** for tome/death; preserve allocation-free hot paths and object ownership.

17. **P1 — `vfx/` is a namespace, not a clear layer graph.** Its 23 modules include generated catalogs, generic particles, a pack composer, weapon-suite runtime, beam rendering, XP rendering and boss-specific rendering. `scenes/arena/vfx.ts` then imports composer/packs/particles directly (`packages/client/src/scenes/arena/vfx.ts:1-10`), while `ArenaScene` imports four VFX entry points (`packages/client/src/scenes/ArenaScene.ts:127-136`). The result is bidirectional conceptual coupling between generic runtime and arena semantics. **Extract/reorganize:** `vfx/catalog/` for generated data, `vfx/runtime/` for canonical renderer/particles/composer, `vfx/renderers/` for Beam/XP/Worm, and `scenes/arena/effects/` for semantic game effects. Add one barrel only at each layer boundary; avoid a global barrel that re-couples all assets. **Effort/safety:** **M / high** as path-only moves with import-graph checks.

18. **P1 — `vfx-render.js` is an intentionally shared classic script, but the TypeScript seam is too permissive to protect either host.** The 1,327-line module has no imports/exports and writes `globalThis.VFXRENDER` (`packages/client/src/vfx/vfx-render.js:11`, `:1312`); `vfx-layers.js` does the same at `packages/client/src/vfx/vfx-layers.js:251`. The ambient declaration accepts wildcard modules, uses many `unknown`s, and declares only part of the live surface (`packages/client/src/vfx/vfx-core.d.ts:3-61`); `VfxPlayer` compensates with repeated `as unknown as` casts (`packages/client/src/vfx/VfxPlayer.ts:240`, `:262`, `:329`, `:357`, `:492`). Actual renderer use includes many undeclared surface fields (`perBody`, `perLip`, `perLoading`, emitters, render options, and more), so drift can compile. **Extract:** retain the classic script for Weaponsmith parity, but put game access behind typed `canonical-vfx-adapter.ts`; generate or hand-maintain a complete shared surface contract and add a runtime shape assertion at startup. Optionally enable `checkJs` on only these files via JSDoc. **Effort/safety:** **M / medium-high**; no renderer conversion is required.

19. **P1 — the generated sprite manifest is correctly marked generated, but its output unit is too broad.** It is explicitly produced by `harvest-install.mjs` (`packages/client/src/sprites/manifest.ts:1`) and consumed as one 405-entry `SPRITES` object. `ArenaScene.preload()` iterates all entries to find boot-loaded loose assets (`packages/client/src/scenes/ArenaScene.ts:1302-1310`), lazy weapon loading indexes it again (`:2311-2339`), and `SpriteRig` construction depends directly on it (`packages/client/src/entities/SpriteRig.ts:1121-1133`). The file is not hand-maintenance debt, but it increases TypeScript parse/type work, makes every generated asset change replace one enormous unit, and prevents narrow pack ownership. **Extract via the generator, never by hand:** emit a small type contract plus core, dimension/character and expansion-weapon manifest shards with a generated index/lookup service. First preserve eager runtime lookup behavior byte-for-byte; optional dynamic chunking can be a later latency change. **Effort/safety:** **L / medium-high**; require byte-for-byte regeneration checks and key/path parity.

20. **P1 — `AudioBus` combines audio graph lifecycle, persistence, voice policy, sample-loop lifecycle and every cue recipe.** The class owns browser/context setup at `packages/client/src/audio/AudioBus.ts:32-206`, primitives and sample-loop management at `:208-400`, then accepts an untyped `event: string` and dispatches every cue in a 560-line switch (`:406-965`). Beam and boss loop work therefore edits the same file as melee, rewards and settings; this is another named in-flight hotspot, so the committed-state basis is important. **Extract:** define an `AudioCue` union and narrow `AudioPrimitives` interface; move recipes into `audio/cues/combat.ts`, `beam.ts`, `rewards.ts`, and `boss.ts`, while `AudioBus` retains context, throttling, voice caps and output. Keep loop lifecycle as a small owned controller. **Effort/safety:** **M-L / medium-high**; use the existing fake-context/sample-bank test style and preserve recipe scheduling order exactly.

### P2 — consistency and secondary debt

21. **P2 — `ui/` contains models/layouts, while Phaser UI construction follows several independent idioms.** Level text uses `levelWindowText()` with DPR resolution (`packages/client/src/scenes/ArenaScene.ts:5068-5077`), bag/arsenal text uses another pool helper (`:8643-8658`), dock art defines its own `dockTextResolution()` from `window.devicePixelRatio` (`packages/client/src/scenes/arena/card-art.ts:163-180`), and `MenuScene` constructs text directly (`packages/client/src/scenes/MenuScene.ts:141-174`). The dock helper also bypasses the capped `RENDER_DPR` that bootstrap declares as the one source of truth (`packages/client/src/render-dpr.ts:1-12`, `packages/client/src/main.ts:13-20`). Hit targets likewise vary between an interactive visible frame (`MenuScene.ts:372-383`), a separate fixed-screen translucent card rectangle (`ArenaScene.ts:5534-5550`), and pooled transparent 1×1 rectangles resized later (`ArenaScene.ts:9023-9046`, `:9239-9270`). 22. **P2 — sprite texture resolution and optional-image loading are owned by large consumers.** `partTexture()` is exported from the 5,513-line `SpriteRig.ts` (`packages/client/src/entities/SpriteRig.ts:65-80`) and imported by card/pickup/projectile code, making the rig file the conceptual asset API. ## Boundary assessment

- **Good precedents to preserve:** pure `SelfPredictor`, `SnapshotBuffer`/`TimelineSync`, `level-up-model`, `level-up-layout`, `weapon-dock-layout`, `XpMoteRenderer`, `BeamRenderer`, projectile factory, and draw utilities. They accept narrow data and do not reach back through the whole scene.
- **What did not hold:** extracting only pure drawing functions while leaving state, pools, input and lifecycle in `ArenaScene`. The next split needs owned controllers with `destroy/reset/update`, otherwise fields and orchestration still collide.
- **SpriteRig style split:** viable, but only after a retained scalar pose frame. Tome, jiggle math, close-blade sampling and paper death can move first. Exporting the current mutating `apply*` methods with a 100-field context would be a cosmetic split and should be rejected.
- **VFX JS seam:** the classic-script constraint is legitimate because Weaponsmith and the game share it. The fix is a complete typed adapter/contract, not a behavior-changing TypeScript rewrite.
- **Generated manifest:** it is generated, not hand-authored debt. Change the generator and add regeneration verification; never manually curate the 13,937-line output.
- **Testing posture for extraction:** the committed client has strong pure net tests and one close-blade pose suite, but no characterization around scene lifecycle, overlays, dock/bag, telegraphs, beam client state or AudioBus recipes. Add scalar/model tests and a minimal Phaser harness before the stateful moves; this is extraction safety, not a request to change behavior.

## Sequenced extraction roadmap

The sequence prioritizes getting future multi-agent waves out of `ArenaScene.ts` and `SpriteRig.ts` as early as possible.

1. **Freeze contracts and create low-risk seams (S-M).** Add committed-state characterization for `update()` phase order, level modal/release behavior, dock state transitions, bag index intents, telegraph geometry, damage recap, beam ack/release, and selected SpriteRig pose samples. Move `partTexture`, optional-image loading, telegraph pure geometry, damage recap, jiggle math and other already-pure helpers. Remove confirmed dead code. No render or input order changes.

2. **Evacuate the three current UI collision zones (L total, separable commits).** Extract in this order: `LevelWindowController`, `WeaponDockView`, then `InventoryPanel` plus `MetaProgressRepository`. Each controller owns its pools, timers and destroy/reset path and emits typed intents. After this phase, level UI, dock and backpack/shop agents should never need to edit `ArenaScene` for ordinary presentation work.

3. **Split `SpriteRig` before another animation wave (L).** Move tome and paper-death controllers, introduce the retained `RigPoseFrame`, then move close-blade and combo/style samplers by vocabulary. Keep final Phaser writes and display-list depth swaps in a much smaller `SpriteRig`. After this phase, jiggle, tome, paper-death and individual combo-family agents have separate files.

4. **Evacuate combat-readability ownership (L).** Extract `TelegraphRenderer`, `BeamHud`, `BeamClient`/`BeamFeedback`, `CombatPresentation`, and `PaperTransitionController`. Preserve exact Graphics depths, budgets, hit-stop order and audio edges. This removes the subsystems responsible for the telegraph, beams, danger/death and paper commit collisions.

5. **Separate world and session infrastructure (L).** Extract `BeltRenderer`/`ArenaProjection`, `ArenaSessionClient`, and `ArenaReplication`; move the worm snapshot ring to `net/`. The scene should receive render samples and semantic events instead of owning transport buffers. Floor assembly can then be split internally without touching the scene.

6. **Extract input and collapse lifecycle last (L).** Once overlays, dock, inventory, beam and session expose narrow APIs, move modal/device policy into `InputRouter`. Replace the 212-line reset census with controller `reset/destroy` calls and keep a small, explicitly ordered frame coordinator in `ArenaScene`. Doing this earlier would encode today's hidden cross-subsystem dependencies into another monolith.

7. **Harden secondary package boundaries (M-L).** Add the typed canonical-VFX adapter, organize the VFX directories, split AudioBus cue recipes, shard the sprite manifest through its generator, and decompose `floor-renderer.ts`. These improve compile/navigation latency and future ownership, but they follow the files currently causing agent queues.

The target is not a tiny scene at any cost. A healthy end state is an `ArenaScene` that visibly owns Phaser lifecycle and the ordered frame phases, while each frequently changing subsystem owns its own retained state, display objects, reset/disposal, tests, and intent boundary. That preserves current behavior and makes parallel waves change different files by construction.
